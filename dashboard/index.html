How Parry works — one request, end to end

The data problem: a busy app emits millions of HTTP events a day. You can't LLM-scan every request — it's too slow and too costly. Parry's answer: parse every request into structured rows, let ClickHouse do detection as SQL at scale in milliseconds, and spend the LLM only on the handful of events that already look like an attack. Each stage below names the sponsor, what it does, how we use it, and when it fires.

Every lane is optional — unset a key and Parry degrades to the lanes that remain, never breaks.
